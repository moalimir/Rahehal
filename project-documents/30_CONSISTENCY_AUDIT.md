## E. What is genuinely strong (keep, don't rebuild)

Not everything is a problem — these are assets to preserve and build _on_:

1. **`packages/domain/src/challenge.ts` + `domain/state-machines.ts`** — a shared 11-stage challenge machine plus rich sub-entity transition tables with roles/preconditions/side-effects/notification/audit/retry. **Keep as canonical or migrate slice-by-slice into the shared package** (20 §4.2).
2. **`domain/solver.ts` + `lib/solver/repository/`** — a v5 aggregate with migrations, idempotency map, typed `MutationResult`, receipts, audit events, workspace isolation, cross-tab events. **This is the backend command-layer template** (20 §9).
3. **`decideTeamPermission`** — a real deny-by-default, policy-driven RBAC with human-readable reasons. **Keep as the authz test oracle** (70 §5).
4. **Negative-state vocabulary** — loading/empty/partial/error/offline/permission/locked/conflict/closed/success, plus non-enumerating not-found. **Rare and valuable; carry into API error contract.**
5. **Zero import cycles**, strict TS, and a large green test suite — a healthy base to refactor from.
